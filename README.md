# Кости и Судьбы 🎲

Мобильная **текстовая RPG с ИИ-мастером**: игра сама описывает сцены, рисует картинку окружения
и предлагает варианты действий. Каждое действие — бросок d20 с анимацией кубика, шансом успеха
и последствиями. Отдельно есть **конструктор своего мира** и режимы по известным играм.

Сделано под телефон, в первую очередь под **iPhone 13 mini (375×812)**, но работает на любом экране.
Сохранения живут в `localStorage` браузера + экспорт/импорт файлом.

## Что нового в v5.1

* **Текст мастера печатается медленнее и ровнее** — примерно 24 мс на знак (2,6–9 с на сцену
  вместо прежних ~1,4 с рывками), а тап по тексту показывает его целиком.
* **Ожидание переехало наверх**: строка «⏳ Мастер описывает последствия…» со спиннером живёт
  в шапке под названием игры, шапка стала выше (14% против 8%), а внизу на месте будущих
  вариантов мерцают аккуратные заготовки вместо пустого поля.

## Что нового в v5

| Запрос | Что сделано |
|---|---|
| «Своя игра»: ИИ сам убирает неподходящие параметры героя | Мастер в ответе о мире возвращает **профиль создания героя**: свои названия шагов («Школа», «Роль»), свой список классов/рас/происхождений. Пустой список = **шаг не показывается**: в мире «Ведьмак 3» раса не спрашивается, в Киберпанке — тоже. Пролог закрывается один раз, дальше доступен кнопкой «Пролог» в игре и хранится в сохранении |
| Фон должен соответствовать рассказу и показывать действующих лиц | Мгновенный canvas-фон рисует **героя, противников и предметы сцены**: силуэты берутся из текста хода (бандиты, волк, дракон, костёр, повозка, башня…), герой — слева лицом к врагам, у каждой фигуры светящаяся кромка. Промпт для ИИ-картинки тоже дополняется героем и врагами сцены |

## Экраны

1. **Меню** — сгенерированная абстракция на фоне, кнопки «Начать новую игру» и «Мои игры»,
   настройки, переключатель звука, индикатор связи с ИИ.
   Внизу по экрану носится **смешной рисованный рыцарь**, а за ним по пятам — **красный дракоша**:
   иногда дракоша бежит первым, иногда отстаёт; бег — покадровая анимация ног, крыльев и пыли из-под ног.
   Оба нарисованы кодом (SVG), поэтому работают без сети и в однофайловой сборке. По герою можно
   щёлкнуть — он подпрыгнет и скажет что-нибудь. При переходе в другую меню бег останавливается,
   а при системной настройке «уменьшить движение» герои просто стоят по краям.
2. **Выбор мира** — три вкладки:
   * **Случайные** — подборка из 3–4 сценариев (лес Аскельда, затонувшая Аврелия,
     станция «Гелиос-9», нуарный Грейхейвен, пустошь Кар-Ата) с обложками;
   * **По играм** — Азерот, Найт-Сити, Рунитерра, а также **«своя игра»**: игрок пишет
     название игры (например, «Ведьмак 3»), и мастер строит мир по её духу;
   * **Свой мир** — конструктор: жанр, тон, место старта, роль героя, цель, особенности мира,
     уровень опасности. Всё выбирается чипами или пишется текстом. Набор можно сохранить
     («Сохранённые миры») и переиспользовать.
3. **Создание героя** — имя (кнопка случайного имени), **класс**, **раса/вид**,
   **происхождение** и превью итоговых характеристик и здоровья. В «своей игре» шаги и подписи
   задаёт мастер: лишние секции скрываются, а под именем видно его пояснение
   («🧠 Мастер: в этой истории все — люди, поэтому выбирается только школа и происхождение»).
4. **Игра** — шапка **14%** высоты: название, глава и ход, здоровье, ×, а под ними —
   строка состояния мастера («⏳ Мастер описывает последствия…» со спиннером), поэтому ожидание
   видно вверху и низ экрана не пустует.
   **Картинка сцены 22%** (мгновенный canvas-фон + ИИ-иллюстрация сверху), текст сцены
   печатается спокойной волной (~24 мс на знак, тап по тексту показывает его целиком),
   кнопка умения, кнопки действий со шансом успеха и характеристикой; пока мастер думает,
   на их месте стоят мерцающие заготовки.
   Первый ход открывает **«Пролог»** на весь экран; позже его можно перечитать кнопкой «Пролог».
5. **Мои игры** — сохранения с обложкой, главой, здоровьем и временем, экспорт/импорт JSON.

Плюс: модальные окна (герой, закрытие игры, настройки), тосты-уведомления,
настройка Pollinations-ключа, звуки, поддержка `prefers-reduced-motion`.

## Система вероятностей

* Бросок **d20** — на экране анимируется столько раз, сколько «миганий» соответствует значению;
  выпавшее число и есть результат (никакой подмены графики).
* Итог: `d20 + модификатор характеристики` против **сложности** (легко 8 / средне 11 / трудно 14 / смертельно 17).
* **20** — критический успех, **1** — критический провал, независимо от суммы.
* **Уровень опасности мира** сдвигает сложность: мягкий −2, сбалансированный 0, жестокий +2.
* На каждой кнопке показан честный шанс успеха в процентах (с учётом преимущества).
* **Умения классов** действуют один ход и восстанавливаются через 3 хода: «Второе дыхание» (+4 HP),
  «Анализ»/«Натиск слов»/«Чутьё» (+3 к броску), «Тень»/«Искра» (преимущество: два d20, берём лучший).

## Своя игра: как это устроено

1. Игрок пишет название игры (или собирает мир в конструкторе), и **до** создания героя игра
   просит мастера собрать мир. Ответ содержит `world` (о мире), `backstory` (предыстория героя),
   `plan` (3 шага отыгрыша) и `hero` — контракт создания героя:

   ```json
   { "classLabel": "Школа",
     "classes": [{ "id": "mage", "title": "Ведьмак", "hint": "мутации, два меча, медальон" }],
     "races": [],
     "origins": [{ "id": "soldier", "title": "Школа Волка", "hint": "наставник погиб" }],
     "note": "в этой истории все — люди" }
   ```

2. Пустые `races` или `origins` — команда «этот шаг не показывать». Незнакомые id отбрасываются,
   классы никогда не остаются пустыми. Если мастер недоступен, профиль подставляет встроенная
   таблица знакомых игр (`E.offlineHeroProfile`): Ведьмак, Cyberpunk 2077, World of Warcraft,
   League of Legends, GTA.

3. Пролог хранится в сохранении (`game.intro`, `game.introSeen`) и переживает перезагрузку страницы.

## Свой сервер на GitHub Pages

GitHub Pages отдаёт только статику, поэтому `/api/*` там нет и игра уходит в локальный режим.
Чтобы страница использовала бэкенд с Render, достаточно открыть её со ссылкой:

```
https://ваш-логин.github.io/dice-tales/index.html?server=https://dice-tales.onrender.com
```

Адрес запоминается в `localStorage` (`dt2:server`), его же можно задать программно
(`DTapi.setServerBase('https://…')`). Без адреса игра полностью играбельна:
мастер — локальный, картинка — мгновенный процедурный фон.

## Как ИИ отвечает: три уровня отказоустойчивости

1. **Серверный прокси** `/api/gm` — перебирает доступные провайдеры (Groq → Gemini → OpenRouter →
   OpenAI → Pollinations с ключом → анонимно), отдаёт первый успешный ответ.
2. **Прямой запрос из браузера** — если сервера нет (например, страница открыта как файл на GitHub Pages).
   Работает на вшитом ключе; без ключа Pollinations требует Turnstile-токен и этот путь отваливается.
3. **Локальный мастер** `E.offlineTurn` — заранее написанные сюжетные ветки для каждого мира:
   игра продолжается даже без интернета, сцену и варианты действий придумывает сама игра.

Картинки работают так же: **мгновенно** рисуется процедурный фон на canvas, а параллельно
запускается гонка источников (серверный кэш → a0.dev → Pollinations → picsum);
побеждает тот, кто ответил первым, остальные запросы отменяются. Результат кладётся в кэш.

## Запуск

```bash
npm start                 # сервер на http://localhost:3000 (и /game.html — вся игра одним файлом)
npm test                  # 34 теста логики
npm run build             # пересобрать game.html
npm run smoke             # прогон интерфейса в headless-Chromium (iPhone 13 mini)
npm run smoke:live        # то же, но с настоящими ИИ-каналами
npm run layout            # проверка раскладки на 5 телефонах (14% / 22%)
npm run check             # синтаксис + тесты + раскладка
```

### Ключ Pollinations

Ключ уже вшит в проект (`src/api.js` → `BUILTIN_API_KEY`, `server.js` → `POLLINATIONS_KEY`),
поэтому ИИ-мастер и генератор картинок работают сразу после деплоя, без настройки.
Свой ключ можно вставить в настройках игры (⚙️) или через `?key=…` в адресе страницы —
он переопределит вшитый. Если передать пустое значение, игра вернётся к встроенному ключу.

### Переменные окружения (сервер, все необязательны)

`GROQ_API_KEY`, `GEMINI_API_KEY`, `OPENROUTER_API_KEY`, `OPENAI_API_KEY` (+`OPENAI_BASE_URL`, `OPENAI_MODEL`),
`POLLINATIONS_API_KEY` (переопределяет вшитый ключ), `PORT`, `HOST`.
Без ключей сервер всё равно работает — через анонимный канал и локального мастера.

⚠️ Ключ лежит в открытом виде в коде и в собранном `game.html`. Это осознанное решение автора игры:
так она работает у любого, кто просто открыл файл. Если репозиторий публичный и ключ жалко —
переопределите его переменной окружения (на сервере) или своим ключом в настройках.

### Деплой

* **GitHub Pages** — достаточно положить `game.html` (или `index.html` + `assets/` + `src/`).
  Сеть к ИИ может быть недоступна: игра сама переключится на локального мастера, сохраняя всё остальное.
* **Render** — `render.yaml` уже описывает сервис: `npm start`, живой прокси `/api/gm` и `/api/image`.
